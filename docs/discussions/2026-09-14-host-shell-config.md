# 2026-09-14 · 宿主薄壳、配置分层与组装层零件

> 商讨记录（约定见 [README](README.md)）。本篇的**已定稿部分已合入** [06-host-shell.md](../06-host-shell.md)（全篇）、[03](../03-context-build.md) §5/§6、[README](../README.md) 决策速览 11/12、[05](../05-open-questions.md) A2/C4/E4/G0b。本记录保留备选方案与被否理由。

## 背景

MVP 收敛为「终端手打替代 ASR」并跑通后（同日早些时候），用户提出：完善配置 + 要一个可操作界面（web）+ 在网页上做对话测试。讨论中逐步澄清为：

- **配置是主体，网页是它的操作面**（设置面板为主 + 对话测试页）；「对话测试」= 在网页上直接聊，不另造断言框架；
- 边界修正：**`window` 是组装层，压缩只是它里面的一个可换零件**（用户纠正——我此前一直把它叫「压缩层」，把这一层说小了）；
- 输入源与压缩同构：**骨架 + 组装层（含零件位）+ 输入插头**。

## 决策

### D1 · 配置：启动读一次，运行期只写回（合入 06 §3）

```
启动：读文件 → 内存（唯一真相）
运行：web 改 → 内存立即生效 → 原子写回文件（只为下次启动）
重启：文件把状态还回来
```

- 用户定调：「config 只在启动时读取一次，然后我们只做写回；主要通过 web 来控制配置，然后文件来持久化」；
- 保留两层文件（`aria.toml` 人写只读 + `aria.override.toml` 机器写），因为这正好治住唯一的残留问题——写回会吃掉注释；
- **不做任何自动监听**：文件级监听的原子保存盲区、mtime 粒度这些坑随之消失（不监听就没有漏事件）。外部手改后生效 = `Manager.Reload()` 显式重读（面板留一个「重新读取」按钮）或重启；
- 程序写回走原子写（临时文件 + 改名）；写失败不静默。

演进过程：先实现「2 秒内容比对轮询」，再补「目录级事件监听 + 内容比对 + 兜底轮询」三层（见下方被否方案 3/4 的说明），用户提出读一次+只写回后**整段删除**——这是本次讨论里最值的一次简化：问题不是被解决了，而是被设计掉了。

### D2 · 组装层的骨架/零件分界（合入 03 §5）

| 部分 | 性质 |
|---|---|
| 排列顺序、压缩中不丢内容、失败退回原文 | 骨架（不动） |
| 压缩策略（keeplast / provider / 将来 twopart） | 零件位①（配置点菜 + 热切换） |
| 记忆包装与标签 | 零件位②（暂定死） |
| `<context>` 背景资料槽（M3） | 零件位③（预留） |

零件装配在宿主侧（名字→实现的注册表），`window` 只认 `Compressor` 接口；热切换用 `SetCompressor`（在途压缩用旧实现跑完）。要完全自定义组装链走 core 槽 1 `Assembler`。

### D3 · 输入插头（合入 06 §2）

引擎输入口只有一个；插头交付「一句完整的话 + 谁说的」，**各自判断「说完」**（手打=回车、ASR=静音 1s〔服务端已做端点检测〕、网页=点发送）。多插头并存 → 排队（一次一轮）；照片等强关联感知**不是插头**，随话语进同一条消息的多模态块。

### D4 · 认主挂起，归插件层协商（合入 03 §6、05 E4）

用户判断：「这个是插件的事，需要在插件里协商。放着先」。runtime 只保留设计位（输入必须带主人；说话人落 Message/Scope 两处）。可行阶梯留给插件层按需议定：数人头 → 唇动 → 声纹 → 名册。

### D5 · 打断暂缓

用户判断：「打断实现也比较头疼」。v1 排队语义已够（AI 说话时来的话等它说完再进）；打断（Interrupt + 小轮垫话）按 03 §7 设计保留，随语音接入时再做。**澄清**：此前表述「边听边打字抢话」不准确——排队 ≠ 抢话。

## 被否方案与理由

1. **零第三方依赖**（我最初提议 JSON 配置以避免引入依赖）——用户明确否掉（"什么时候要求0依赖了"）；这只是从 go.mod 现状推来的洁癖，不是项目约束。改用 viper + TOML（能写注释）。
2. **单文件配置 + 程序回写**——被否：viper `WriteConfig` 把整个文件解析成 map 再重写，**注释必丢**（[viper#1104](https://github.com/spf13/viper/discussions/1104)，官方无修复计划），人写的说明文字会消失。改为两层文件，程序永不碰 base。
3. **`viper.WatchConfig()`（fsnotify）**——被否：[viper#142](https://github.com/spf13/viper/issues/142)，编辑器原子保存（写临时文件 + rename）替换文件对象，文件级监听静默失效。后续曾用「目录级监听」（盯文件夹而非文件，改名也看得到）绕开它，但随 D1 改为「读一次 + 只写回」后整段删除——**不监听就没有漏事件**。
4. **mtime 轮询**——被否且**实测打脸**：本机文件系统时间戳粒度粗到 tmp+rename 前后 mtime **完全相同**（调试输出确认），会漏变更。曾改为内容比对轮询，同样随 D1 删除；`Reload()` 显式重读时仍用内容比对（空写/未变不通知）。
5. **脚本化对话测试（场景文件 + 断言 + 报告）**——我一度设计成 TOML 场景 + 五个断言词 + 报告；用户纠正：「我是说在网页上做对话测试」——网页上聊即测试，不另造框架。断言式场景保留为将来可选项（未列入 06 未落地清单）。
6. **把窗口整体插件化（连顺序/防丢保护都能配）**——被否：顺序是前缀缓存与分层安全的载体、防丢是正确性本体，开放配置等于把 bug 变成用户选项。
7. **前端工程（vite/react）**——暂否：`go:embed` 单页静态零构建链，仓库保持「克隆即跑」；面板复杂到撑不住再迁。
