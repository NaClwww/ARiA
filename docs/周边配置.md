## 1. ASR（:8200）

两套引擎并存，按用途分：

- **批量**：`Qwen3-ASR-0.6B-8bit`（MLX，Apple Silicon 量化，默认 `mlx-community/Qwen3-ASR-0.6B-8bit`）。
  任意容器/编码（ogg/opus、wav、mp3…）经 PyAV 解码成 16k 单声道再识别。适合"一次性拿到整段文本"。
- **实时流**：`paraformer-zh-streaming`（FunASR，CPU）。600ms 步进、状态跨块延续的真流式，无滚动重解码，
  文字比语音滞后约 0.3~0.9s。**这是给编排/agent 用的主接口**，服务启动时自动常驻拉设备麦克风。

### 1.1 实时事件流 `GET /asr/events`（SSE，推荐）

服务启动即建立一条到设备麦克风的常驻连接（`MIC_STREAM_URL`），在服务端做端点检测，
把识别结果以 SSE 推给所有订阅者。**调用方只需订阅，不用自己管麦克风。**

```bash
curl -N http://127.0.0.1:8200/asr/events
```

事件格式（`data:` 一行一个 JSON，UTF-8 不转义）：

```jsonc
{"type":"partial","text":"今天天气","t":1757850000.12}                 // 说话中，可反复出现
{"type":"final",  "text":"今天天气怎么样","wav":"utt_00007.wav","t":…}  // 一句说完
```

- `partial`：当前句的累积假设，**会不断刷新**，适合做"实时字幕"。
- `final`：端点检测触发后的定稿，**一句话只来一次**，适合送 LLM。`wav` 是落盘的整句音频
  （`services/logs/mic_segments/utt_00007.wav`，`MIC_SAVE_SEG=0` 可关）。
- 15s 无事件时收到注释行 `: keepalive`，客户端应忽略注释行、不要断连重连。
- 多客户端可同时订阅（内部 pubsub，队列满丢事件不阻塞）。

Python 消费示例：

```python
import json, requests
with requests.get("http://127.0.0.1:8200/asr/events", stream=True) as r:
    for line in r.iter_lines(decode_unicode=True):
        if not line or line.startswith(":"):     # keepalive / connected
            continue
        ev = json.loads(line.removeprefix("data: "))
        if ev["type"] == "final":
            send_to_llm(ev["text"])               # 只在 final 上动作
```

### 1.2 端点检测与调参

服务端按 30ms 帧算 RMS 判定"有声/静音"，逻辑在 `asr_stream.py`：

- 静音达到 `MIC_ENDPOINT_S`（默认 **1.0s**）且本句有效语音 ≥ `MIC_MIN_VOICE_S`（默认 **0.25s**）→ 出 `final`。
- 有效语音不足（噪声毛刺）→ 丢弃该段，不出 final。
- 单句最长 `MIC_MAX_SEG_S`（默认 60s），超了强制 final。

| 环境变量 | 默认 | 说明 |
|---|---|---|
| `MIC_STREAM_URL` | `http://172.16.48.172:8900/api/voice/mic/stream` | 设备麦克风流地址 |
| `MIC_ENDPOINT_S` | `1.0` | 多长静音算说完（调大=更耐停顿，调小=更快响应） |
| `MIC_MIN_VOICE_S` | `0.25` | 一句至少要有多久有效语音才认 |
| `MIC_RUN_THRESH` | `0.003` | 有声判定 RMS 门限（f32）。静音 ~0.0005-0.004，清晰说话 ~0.008-0.018 |
| `MIC_SAVE_SEG` | `1` | 是否把每句落盘 |
| `FUNASR_MODEL` / `FUNASR_DEVICE` | `paraformer-zh-streaming` / `cpu` | 流式模型与设备 |
| `ASR_MODEL_ID` | `mlx-community/Qwen3-ASR-0.6B-8bit` | 批量模型（换 1.7B：`mlx-community/Qwen3-ASR-1.7B-8bit`） |

运行时可查状态、可热调门限（不用重启）：

```bash
curl -s http://127.0.0.1:8200/asr/live
# {"enabled":true,"stream":"http://172.16.48.172:8900/api/voice/mic/stream",
#  "connected":true,"noise_floor":0.0012,"segments":3,"last_final":"…",
#  "decodes":812,"voice_s":1.4,"run_thresh":0.003}

curl -s -X POST -d '{"run_thresh":0.005}' http://127.0.0.1:8200/asr/thresh
```

> **连接断了会自动重连**（指数退避 2→30s），`/asr/live` 的 `connected` 与 `last_error` 可判断状态。
> 麦克风是**隐式开启**的：只要有人在读流，设备摄像头/麦克风的 10s 看门狗就不会关它。

### 1.3 批量识别

| 接口 | 用途 |
|---|---|
| `POST /asr` | body 直接是音频字节（任意容器/编码），返回 `{"text":"…"}` |
| `POST /asr/file` | multipart `file=` 上传 |
| `POST /asr-raw?rate=16000` | body 是无头裸 PCM16LE 单声道（网关 :8399 用这条） |

`?language=zh`（默认）/`en`/`auto`。

```bash
say -o /tmp/hello.aiff "今天天气怎么样"
ffmpeg -y -i /tmp/hello.aiff -ar 16000 -ac 1 /tmp/hello.wav
curl -s --data-binary @/tmp/hello.wav http://127.0.0.1:8200/asr
# → {"text":"今天天气怎么样"}
```

### 1.4 坑

- **无回声消除**：设备麦克风会拾到本机外放。TTS 播放期间应**暂停读 mic 流**，否则 ASR 会识别到自己说的话。
  当前 ASR 服务是常驻拉流的，播放前需要一条"暂停/恢复"机制（现在只能停掉 listener 或忽略该时间窗的 final）。
- **launchd plist 过期**：`launchd/local.hupo.asr.plist` 里仍写着 `ASR_MODEL_ID=Qwen/Qwen3-ASR-0.6B-hf`（torch 时代的
  HF 仓库名），而现在的引擎是 MLX（`mlx_audio.stt.load`）。**直接装这个 plist 会让批量 ASR 加载失败**——
  装之前把该环境变量删掉或改成 `mlx-community/Qwen3-ASR-0.6B-8bit`。
- 中文偏置默认开（流式模型偶尔把英文音渲染成字母词会被剔除），`ASR_ZH_BIAS=0` 关闭。

## 2. TTS（:8100）

管线：`edge-tts（zh-CN-XiaoxiaoNeural）→ 16k 单声道 → RVC 音色转换（默认 miku 模型）→ 16bit WAV`。
输出采样率由 **RVC 音色模型**决定，当前 miku 默认模型是 **40000 Hz 单声道 PCM16**。
模型常驻 + 文本哈希磁盘缓存（`tts/cache/`），命中缓存基本是零延迟。

> ⚠️ edge-tts 走微软公网，**断网 / Clash 把 Microsoft 组切到 DIRECT 时合成会失败**（这时流式端点会报错）。

### 2.1 同步合成

| 接口 | 用途 |
|---|---|
| `GET /tts?text=…&speed=5&voice_name=1` | **设备标贝契约**（APK 直接调这条），响应 `audio/wav` |
| `POST /tts` | 内部用，body `{"text":…,"speed":5,"voice":"1"}`，返回 wav |

`GET /tts` 的完整参数（设备发的原样）：`user_id=speech&domain=1&language=zh&speed=<0-10>&volume=4&voice_name=1&rate=4&text=<urlencoded>`。

- **`Content-Type` 不能是 `application/json`**，否则 APK 走错误分支；本服务恒返回 `audio/wav`。
- `text` 为空返回 0.1s 静音 wav（不是错误）。
- `speed` 0~10，5=常速；>10 按 APK 逻辑钳到 5。

```bash
curl -o /tmp/t.wav "http://127.0.0.1:8100/tts?text=%E4%BD%A0%E5%A5%BD%E5%91%80&speed=5&voice_name=1"
afplay /tmp/t.wav
```

### 2.2 流式合成（推荐给 LLM 对接）

RVC 是整句变换（要整段算 HuBERT 特征 + f0），做不到音素级流式。服务端改成
**按句切分 + 流水线**：第 i 句在 RVC 转换时，第 i+1 句已在向 edge-tts 取，首块音频约 1 句后到达，
之后每句约 0.6s 出一块。四个入口等价，按输入形态选：

| 接口 | 输入形态 | 适用 |
|---|---|---|
| `GET /tts/stream?text=…&speed=5` | 整段文本一次给 | 快速验证 |
| `POST /tts/stream` | `{"text":…,"speed":5,"voice":"1"}` | 整段文本一次给 |
| **`POST /tts/stream_input`** | **chunked 请求体 = 文本碎片** | **LLM token 边生成边推（首选）** |
| `WS /tts/ws` | 发 `{"text":"碎片"}`，最后 `{"eos":true}` | 需要双向/长连接的场景 |

响应格式（三个 HTTP 流式口一致）：

- `Content-Type: audio/wav`，body = **12 字节占位 WAV 头**（RIFF/data 长度写 `0xFFFFFFFF`，
  因为总长未知）+ 每句一块 **PCM16LE**。
- 播放器要能接受"长度字段是占位值"的 WAV 流；按块顺序喂给 AudioTrack/播放器即可，读到 EOF 为止。
- WS 口则是：先收二进制 PCM 帧，最后收一条文本 `{"done":true}`。

```bash
# 整段
curl -N -o /tmp/stream.wav "http://127.0.0.1:8100/tts/stream?text=%E4%BD%A0%E5%A5%BD%EF%BC%8C%E4%BB%8A%E5%A4%A9%E5%A4%A9%E6%B0%94%E5%BE%88%E5%A5%BD%E3%80%82"

# 模拟 LLM token 流：分片写 chunked body，服务端边收边合成
printf '你好，' '\n' | curl -N -X POST --data-binary @- \
  "http://127.0.0.1:8100/tts/stream_input?speed=5" -o /tmp/stream2.wav
```

```python
# LLM token 直连：边出 token 边写，边读音频
import requests
with requests.post("http://127.0.0.1:8100/tts/stream_input",
                   data=(tok.encode() for tok in llm_tokens()),   # 生成器 = chunked
                   stream=True) as r:
    for pcm in r.iter_content(4096):
        speaker.write(pcm)     # 跳过前 44 字节 WAV 头
```

### 2.3 音色与开关

| 环境变量 | 默认 | 说明 |
|---|---|---|
| `TTS_DEFAULT_MODEL` | `1a_miku_default_rvc_(aple)` | 默认 RVC 模型目录名 |
| `TTS_VOICE_MAP` | `weights/voice_map.json` | `voice_name → weights/ 下模型目录` 的映射 |
| `TTS_RVC_ENABLED` | `1` | `0` = 跳过 RVC，直接出 edge-tts 原声（快得多，调试用） |
| `TTS_EDGE_VOICE` | `zh-CN-XiaoxiaoNeural` | edge-tts 基础音色 |
| `TTS_ENGINE` | `edge` | 可切 `moss`（本地 MOSS-TTS，:8301；失败自动回落 edge） |

换音色：把任意 RVC 模型的 `.pth`（+ `.index`）丢进 `weights/<名字>/`，再在 `voice_map.json` 里映射即可。

## 3. 视频流（设备摄像头）

设备后置摄像头，**640×480 MJPEG**，与 Live2D/l3d 渲染并行互不影响（实测模型 FPS 无变化）。
服务在设备端 `:8900`（NanoHTTPD），**无鉴权、局域网明文**。

### 3.1 接口

| 接口 | 说明 |
|---|---|
| `GET /api/camera` | 状态：`{"available","on","explicit","clients","width","height","fps","quality","frame_seq"}` |
| `POST /api/camera` | `{"on":true}` 显式开 / `{"on":false}` 关；`{"quality":30..95}` 调 JPEG 质量（默认 60） |
| **`GET /api/camera/stream`** | **MJPEG 实时流**，`multipart/x-mixed-replace; boundary=frame` |
| `GET /api/camera/frame` | 单帧 JPEG（`image/jpeg`），抓一张就走 |

```bash
BASE=http://172.16.48.172:8900
curl -s "$BASE/api/camera"                       # 看状态（不改变任何东西）
curl -s -m 5 -o stream.mjpeg "$BASE/api/camera/stream"   # 抓 5 秒流
curl -s -o snap.jpg "$BASE/api/camera/frame"     # 单帧
# 浏览器直接打开 http://172.16.48.172:8900/api/camera/stream 也能实时预览
```

### 3.2 生命周期（省电 + 隐私，必须知道）

```
POST {"on":true}          ──显式开启──▶ 常开，直到 POST {"on":false}（耗电，没人取帧也一直编码）
GET  /stream | /frame     ──隐式开启──▶ 无人取帧持续 10s 后看门狗自动关机
POST {"on":false}         ──显式关闭──▶ 立即关，进行中的流收到 EOF，且不会复活
```

- **只要有人在读流，摄像头就一直开着**（隐式开启会被持续读流续命）。想关就停掉读流方，或显式 `{"on":false}`。
- 流 EOF 的三种原因：客户端断开（正常）、被显式关闭、连续 15s 无新帧。**EOF 后客户端重连即恢复**，所以客户端一定要带重连循环。
- 隐式开启有 ~1s 首帧预热；`503 camera warming up` 稍后重试即可。

### 3.3 解析 MJPEG 的正确姿势

不要依赖 multipart 头格式（设备实现可能有出入），**直接扫 JPEG 哨兵**最稳——
Mac 侧 `face/face_tracker.py` 就是这么做的，可直接抄：

```python
SOI, EOI = b"\xff\xd8", b"\xff\xd9"
buf = b""
with requests.get(STREAM_URL, stream=True, timeout=(3, 15)) as r:   # 连不上/卡住都要能退出
    for chunk in r.iter_content(8192):
        buf += chunk
        while True:
            i = buf.find(SOI)
            if i < 0:
                buf = buf[-2:]; break
            j = buf.find(EOI, i + 2)
            if j < 0:
                buf = buf[i:]; break
            jpeg, buf = buf[i:j + 2], buf[j + 2:]
            frame = cv2.imdecode(np.frombuffer(jpeg, np.uint8), cv2.IMREAD_COLOR)
            # frame 就是最新一帧（640×480 BGR）
```

两个坑：

- **`requests` 要 `trust_env = False`**。这台 Mac 走 Clash TUN，环境里的代理变量会把局域网直连劫持掉。
- **画面是传感器原生方向**（HAL `orientation=180`），设备端不旋转。要正向画面得 Mac 侧处理
  （`cv2.rotate(frame, cv2.ROTATE_180)`），`face_tracker` 用 `FACE_ROTATE` 控制，当前实测已是正向、设为 0。
- 实测吞吐 ~6–7fps / ~60 KB·s⁻¹（限频目标 10fps，源帧率不整除所以隔帧编码）。**无音频轨**，别指望从视频流拿声音，声音走 `/api/voice/mic/stream`。

### 3.4 现成消费者：人脸追踪（:8300）

`face/face_tracker.py` 已经实现了"拉 MJPEG → YuNet 检测 → 取最高置信度人脸 → 换算归一化坐标 →
`POST /api/control/lookat` 眼神随动"，**不用重复造**。模式：`tracking` / `holding`（刚丢脸，设备保持）/
`wander`（丢脸超时，视线游走）/ `device_down`。

```bash
curl -s http://127.0.0.1:8300/health     # mode / conf / lookat / stream_fps / detect_fps
curl -s -o /tmp/dbg.jpg http://127.0.0.1:8300/debug.jpg   # 最新帧叠加检测框+选中脸+模式（调方向用）
```

> 调试人物：想确认"摄像头到底看到了什么"，`/debug.jpg` 最直接。历史上"聚焦中还 wander"的根因就是
> 摄像头视野没对着用户座位（画面里是门/货架），只能物理转设备，代码调不了。

⚠️ 要跑 face_tracker **就得先杀掉旧实例**（`pkill -TERM -f face_tracker.py`）再启动，否则两个实例抢流+对着发 lookat。

## 4. 端到端编排

### 4.1 语音对话闭环（agent 后端要做的事）

```
① 订阅 GET :8200/asr/events（服务已在拉设备麦克风）
② 收到 {"type":"final"} → text → LLM → 回复文本
③ 回复文本边生成边 POST :8100/tts/stream_input（chunked）→ 拿到 PCM16 流
④ 播放 + 口型 + 动作（见下）
⑤ 播放结束后才能继续信任 ASR 结果（防自拾音）
```

**第 ④ 步的播放出口目前有两条路，注意现状**：

| 路线 | 现状 | 做法 |
|---|---|---|
| 设备端播放 | **未实现**（`POST /api/voice/play*` 在 API.md 路线图里，设备源码 `VoiceController` 只有 `mic` 采集，没有播放） | 需先在 live2d launcher 里加 AudioTrack 播放 + 设备端按 RMS 自动喂口型 |
| Mac 侧播放 + 口型下发 | 现在就能用 | Mac 播放音频，同时按 ~30Hz 推 `POST :8900/api/control/lipsync {"level":<音频包络>}`；**停推 150ms 自动闭嘴** |

配合表现（设备 API，见 API.md §6/§8）：

```bash
BASE=http://172.16.48.172:8900
curl -X POST -d '{"group":"w-normal15-greeting"}' "$BASE/api/control/motion"   # 起手动作（Live2D）
curl -X POST -d '{"group":"face_smile_01"}'       "$BASE/api/control/expression"
curl -X POST -d '{"name":"eve_208010101_full_face","loop":true}' "$BASE/api/control/animation"  # l3d 当前模型用这条
curl -X POST -d '{"mode":"blue","blink":true}'    "$BASE/api/light"           # 说话中：蓝闪
curl -X POST -d '{"mode":"stage"}'                "$BASE/api/light"           # 待机：舞台灯
```

> ⚠️ **动作端点分模型类型**：当前设备上屏的是 l3d（`miku_eve`），只能用 `animation`；
> `motion`/`expression`/`lipsync`/`lookat`/`param` 是 Live2D 专属，l3d 上屏时返回 `409`。
> `pose` 和 `animation` 两类通用。

### 4.2 视觉闭环

已由 face_tracker 独立承担（摄像头 → 人脸 → lookat），agent 后端不用管。
若想把"看到人/没看到人"接进对话逻辑，轮询 `GET :8300/health` 的 `mode` 字段即可。

### 4.3 自拾音（最现实的坑）

设备**无回声消除**，麦克风会拾到本机外放。所以：

- TTS 播放期间，ASR 的 `final` 事件不可信；
- 需要在播放前后做门控（暂停订阅 / 丢弃时间窗内事件 / 播放完再清一次缓冲区）；
- 这也是"设备端播放"路线更优的原因——设备端能拿到精确的播放开始/结束时刻。
